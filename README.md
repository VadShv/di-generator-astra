# Генератор ДИ Группы Астра

Корпоративный инструмент для создания и ведения должностных инструкций (ДИ) с
помощью искусственного интеллекта. Сервис помогает крупной компании со множеством
юридических лиц, подразделений и ролей — от разработчиков ИИ до линейного
персонала — быстро выпускать качественные ДИ, поддерживать их в актуальном
состоянии и вести единый реестр.

![Логотип](public/logo.png)

## Что умеет сервис

- **Штатное расписание.** Структура компаний, подразделений и должностей с
  иерархией, детальными карточками и загрузкой из Excel.
- **ИИ-генерация ДИ.** Генерация должностной инструкции по выбранной должности с
  использованием подключаемой ИИ-модели (OpenAI-совместимые API, Yandex Cloud,
  Cloud.ru, локальные LLM через Ollama).
- **Массовая генерация.** Пакетная генерация ДИ по организациям, подразделениям
  или конкретным должностям с очередью, прогрессом и пакетным аудитом.
- **Мастер-промпты.** Библиотека шаблонов запросов с категориями, версионированием
  и переменными; специальный промпт «Культура ИИ» добавляет в ДИ раздел про
  взаимодействие с системами ИИ.
- **Архив ДИ.** Загрузка и хранение старых ДИ (PDF/DOCX) с распознаванием текста,
  привязкой к должности и поиском.
- **Сравнение версий.** Построчное сравнение ДИ между собой и с архивными
  версиями, автоматическое сохранение оригинала.
- **Аудит ДИ.** Автоматическая проверка сгенерированных ДИ на ошибки и пробелы с
  рекомендациями.
- **Отслеживание.** Дашборд: подразделение → должность → статус ДИ
  (актуальна / требует обновления / отсутствует) с экспортом отчёта в Excel.
- **Экспорт.** Выгрузка готовых ДИ в DOCX.

## Стек технологий

| Слой | Технология |
| --- | --- |
| Фронтенд | Next.js 16, React 19, TypeScript |
| UI | Tailwind CSS 4, shadcn/ui |
| Бэкенд | Next.js API Routes (Route Handlers) |
| База данных | PostgreSQL 16 + Prisma ORM 6 |
| Парсинг файлов | xlsx (Excel), pdf-parse (PDF), mammoth (DOCX) |
| ИИ | Универсальный коннектор (OpenAI-совместимый протокол) |

## Требования

- PostgreSQL 16 (локально или удалённо)
- Bun или Node.js 20+
- Доступ хотя бы к одной ИИ-модели (OpenAI-совместимый endpoint)

## Быстрый старт

### 1. Установить зависимости

```bash
bun install
```

### 2. Настроить подключение к базе данных

В файле `.env` укажите строку подключения к PostgreSQL:

```env
DATABASE_URL="postgresql://astra:astra@localhost:5432/di_generator"
```

Для локального PostgreSQL без прав root в репозитории есть скрипт
`scripts/start-postgres.sh` (portable-сборка PostgreSQL 16). Создать базу:

```bash
createdb di_generator
```

### 3. Применить схему и сгенерировать клиент Prisma

```bash
bun run db:push
bun run db:generate
```

### 4. Запустить дев-сервер

```bash
bun run dev
```

Приложение откроется по адресу http://localhost:3001

### 5. (Опционально) Сборка и прод-запуск

```bash
bun run build
bun run start
```

## Настройка ИИ-провайдера

После запуска откройте вкладку **«ИИ-провайдеры»** и добавьте подключение:

- **Тип:** OpenAI-compatible / Yandex Cloud / Cloud.ru / Ollama
- **Base URL** и **API-ключ**
- **Имя модели**

Кнопка «Проверить соединение» отправляет тестовый запрос. Один из провайдеров
помечается активным — именно он используется для генерации ДИ.

## Модели данных (кратко)

Полная схема — в `prisma/schema.prisma`. Основные сущности:

- **Company** — юридическое лицо (название, ИНН, ОГРН, адреса, директор)
- **Department** — подразделение с иерархией (`parentId`, `companyId`)
- **Position** — должность с привязкой к подразделению, грейдом, ставками
- **StaffingTable** — штатное расписание
- **DITemplate / DITemplateSection** — шаблон ДИ и его секции
- **GeneratedDI / GeneratedDISection** — сгенерированная ДИ и её разделы
- **ArchiveDI** — архивная (старая) ДИ, может быть непривязанной к должности
- **UploadedDocument** — загруженный файл старой ДИ с распознанным текстом
- **MasterPrompt / MasterPromptVersion** — мастер-промпты и история версий
- **AIProvider** — подключение к ИИ-модели
- **DITracking** — статус ДИ по должности
- **DIAuditResult** — результат аудита ДИ
- **DIVersion** — история версий ДИ
