# ТЗ: Карточки должностных инструкций (ДИ)

> Версия 1.0 · 2026-07-25
> Связанные разделы: AGENT_LOG.md §18 (Архив ДИ), §22 (связность сущностей), TZ_MASTER_PROMPTS.md

---

## 1. Цель

Унифицировать представление и работу с должностными инструкциями во всех
вкладках сервиса. Ввести 4 типа ДИ, единую карточку ДИ с обязательным набором
поля, единый каскадный селектор (компания → подразделение → должность) и
поддержку создания новой ДИ на базе архивной ДИ и шаблона.

---

## 2. Типы ДИ

Все ДИ делятся на 4 типа. Тип определяется моделью + статусом:

| № | Тип | Источник в БД | Условие |
|---|-----|---------------|---------|
| 1 | **Архивная ДИ** | `ArchiveDI` | — (любая запись в архиве) |
| 2 | **Сгенерированная ДИ** | `GeneratedDI` | `status = 'draft'` |
| 3 | **ДИ на согласовании** | `GeneratedDI` | `status = 'review'` |
| 4 | **Согласованная ДИ** | `GeneratedDI` | `status = 'approved'` |

Правила перехода типов (жизненный цикл сгенерированной ДИ):

```
Сгенерированная (draft) ──отправить на согласование──▶ ДИ на согласовании (review)
ДИ на согласовании (review) ──утвердить──▶ Согласованная (approved)
ДИ на согласовании (review) ──вернуть на доработку──▶ Сгенерированная (draft)
Согласованная (approved) ──перевыпустить──▶ новая Сгенерированная (draft), старая в архив версий
```

Архивные ДИ — отдельная сущность, не имеют статуса жизненного цикла.
Они служат **референсом и базой** для генерации новых ДИ.

### 2.1. Визуальная индикация типов

Каждый тип имеет фирменный цвет и иконку (единый стиль во всех вкладках):

| Тип | Цвет | Иконка (lucide) |
|-----|------|-----------------|
| Архивная | серый/slate | `Archive` |
| Сгенерированная | фиолетовый/violet | `Sparkles` |
| На согласовании | янтарный/amber | `Clock` / `FileClock` |
| Согласованная | изумрудный/emerald | `CheckCircle2` / `BadgeCheck` |

## 3. Единая карточка ДИ

Карточка ДИ — единый компонент `<DICard />`, используемый во всех вкладках,
где показываются ДИ (архив, генерация, отслеживание, сравнение, рабочее
пространство должности, AI-аудит).

### 3.1. Обязательные поля карточки

Карточка всегда содержит:

| Поле | Источник | Примечание |
|------|----------|------------|
| **Идентификатор** | `id` (cuid) | Отображается моноширинным шрифтом, сокращённо `…a4rxlqec`, по клику — копировать полный ID |
| **Тип ДИ** | вычисляется (см. §2) | Цветной бейдж с иконкой |
| **Название** | `title` | Заголовок карточки |
| **Компания** | `position.department.company.name` | С иконкой `Building2` |
| **Подразделение** | `position.department.name` | С иконкой `Users` |
| **Должность** | `position.title` (+ `code`) | С иконкой `Briefcase` |
| **Дата создания/загрузки** | `createdAt` (для архивной — `uploadedAt`) | Формат `ДД.ММ.ГГГГ` |
| **Текст ДИ** | `content` / секции | Сворачиваемый предпросмотр (первые ~500 символов), кнопка «Развернуть» / «Открыть полностью» |

### 3.2. Опциональные поля (по типу)

| Поле | Для каких типов | Источник |
|------|-----------------|----------|
| Версия | сгенерированная, на согласовании, согласованная | `currentVersion` |
| Шаблон | сгенерированная+ | `template.name` |
| Мастер-промпт | сгенерированная+ | последний применённый промпт |
| ИИ-провайдер | сгенерированная+ | использованный `AIProvider` |
| Имя файла | архивная, ДИ с правками | `fileName` |
| Автор/кто загрузил | все | `uploadedBy` / `createdBy` |
| Оценка аудита | сгенерированная+, согласованная | `DIAuditResult.overallScore` |
| Статус согласования | на согласовании, согласованная | assignee, дата отправки |

### 3.3. Действия на карточке (контекстное меню)

Набор действий зависит от типа и от вкладки, но сами кнопки единые:

- **Открыть** — полный просмотр текста.
- **Редактировать** — для draft (переход в редактор секций).
- **Отправить на согласование** — draft → review.
- **Утвердить** — review → approved (роль согласующего).
- **Вернуть на доработку** — review → draft с комментарием.
- **Загрузить версию с правками** — загрузить DOCX/PDF от руководителя (создаёт `DIVersion`).
- **Сравнить** — выбрать вторую ДИ/версию для diff.
- **Выгрузить** — экспорт в DOCX.
- **Создать на базе** — (для архивной) открыть генерацию с этой ДИ как базой.
- **Удалить** — с подтверждением; для approved — только через архивацию.

### 3.4. Верстка карточки

- Карточка занимает ~всю ширину контейнера, минимальная высота ~180px.
- Шапка: тип-бейдж + название + идентификатор + дата (одна строка, адаптивно).
- Тело: текст предпросмотром + строка «компания · подразделение · должность».
- Подвал: кнопки действий (при hover или всегда — по настройке `actionsVisible`).
- Состояния: `loading` (skeleton), `empty` (пусто), `error`.
- Адаптив: на мобильных карточка в одну колонку, кнопки в dropdown-меню.

## 4. Генерация новой ДИ на базе архивной ДИ и шаблона

### 4.1. Постановка

Новые ДИ могут создаваться на базе **архивных ДИ** (как референсный текст) и
**шаблонов** (как структура секций). Поэтому при генерации новой ДИ пользователь
должен выбрать:

1. **Должность** (через единый каскадный селектор, см. §5) — обязательно.
2. **Шаблон** — обязательно (определяет секции).
3. **Архивную ДИ** — необязательно, но рекомендуется (подаётся в промпт как
   референс «как было раньше»).
4. **Мастер-промпт** — необязательно (по умолчанию авто-резолв, см. §22.5).

### 4.2. Изменения в UI генерации

В форме ИИ-генерации (`generation.tsx` и `position-di-workspace.tsx`) после
выбора должности и шаблона добавить блок «Базовая архивная ДИ»:

- Селектор архивных ДИ, отфильтрованный по выбранной должности
  (`GET /api/archive-di?positionId=…`).
- Если у должности нет архивных ДИ — селектор отключён с подсказкой
  «Нет архивных ДИ для этой должности — генерация по шаблону».
- Опционально: галочка «Использовать архивную ДИ как референс» (по умолчанию вкл,
  если архивная ДИ выбрана).

### 4.3. Изменения в API

`POST /api/generate-di/ai-generate` — расширить тело запроса:

```jsonc
{
  "positionId": "...",        // обязательно
  "templateId": "...",        // обязательно
  "masterPromptId": "...",    // необязательно (Фаза 22 — уже поддерживается)
  "archiveDIId": "...",       // необязательно, НОВОЕ
  "useArchiveAsReference": true  // необязательно, по умолчанию true если archiveDIId задан
}
```

Логика сервера:
- Если `archiveDIId` передан — загрузить `ArchiveDI` по ID, проверить привязку
  к той же должности (или разрешить cross-должности с предупреждением).
- Текст архивной ДИ добавляется в user-message промпта как блок
  «Референс — предыдущая редакция должностной инструкции».
- Сохранить связь: в `GeneratedDI` (или в `DIVersion` с `isOriginal=false`)
  зафиксировать, на базе какой архивной ДИ создана.

### 4.4. Связь «создана на базе»

Добавить в схему опциональное поле `sourceArchiveId String?` в `GeneratedDI`
с relation к `ArchiveDI` (`onDelete: SetNull`). Это позволит:
- Показывать в карточке сгенерированной ДИ бейдж «на базе архивной ДИ от ДД.ММ.ГГГГ».
- В архивной ДИ показывать список «производных» сгенерированных ДИ.

## 5. Единая структура поиска и выбора (компания → подразделение → должность)

### 5.1. Принцип

Во **всех** вкладках, где есть поиск или выбор ДИ/должности, используется
**единый каскадный селектор** `CascadePositionSelector` (уже существует,
`src/components/modules/cascade-position-selector.tsx`):

```
Организация → Подразделение → Должность
```

Логика (уже реализована, см. §20 AGENT_LOG):
1. Выбор организации (одна) — активирует шаг 2.
2. Выбор подразделения (из организации) — активирует шаг 3.
3. Выбор должности (из подразделения).

Изменение верхнего уровня сбрасывает нижние.

### 5.2. Где применяется (единообразно)

| Вкладка | Режим выбора | Текущее состояние |
|---------|--------------|-------------------|
| Генерация (обычная) | одиночный | ✅ есть `CascadePositionSelector` |
| Генерация в карточке должности | должность предзадана | ✅ позиция из контекста |
| Массовая генерация | **множественный** | ⚠️ сейчас 3 блока, нужно довести до единого стиля |
| Архив ДИ | одиночный + поиск | ⚠️ есть свой селектор, унифицировать |
| Отслеживание | фильтр + одиночный | ⚠️ унифицировать |
| AI-аудит | одиночный выбор ДИ | ⚠️ унифицировать |
| Сравнение | выбор 2 ДИ | ⚠️ унифицировать |
| Мастер-промпты | фильтр по подразделению | ⚠️ унифицировать |

### 5.3. Множественный режим (для массовой генерации)

Расширить `CascadePositionSelector` пропсом `mode: 'single' | 'multi'`:

- `single` (по умолчанию) — текущее поведение.
- `multi` — после выбора организации можно:
  - выбрать **все подразделения** организации (чекбокс «Все»),
  - выбрать **несколько подразделений** (мультивыбор),
  - в каждом подразделении — выбрать **все должности** или несколько.
- На выходе `onPositionsChange(positionIds: string[])`.

Применяется **только** в массовой генерации. Во всех остальных — `single`.

### 5.4. Единый компонент выбора ДИ

Дополнительно ввести `<DISelector />` — выбор конкретной ДИ после выбора должности:

```
Организация → Подразделение → Должность → ДИ (с фильтром по типу)
```

Используется в AI-аудите, сравнении, отслеживании. Селектор ДИ показывает
карточки-строки с типом-бейджем и датой, с фильтром по типу
(«только согласованные», «только на согласовании» и т.д.).

## 6. Фильтрация и поиск ДИ

### 6.1. Глобальный поиск

Расширить `GET /api/search` (уже ищет по должностям/подразделениям/ДИ) —
добавить в результаты ДИ поле `type` (архивная/сгенерированная/на согласовании/
согласованная) для цветовой индикации в выдаче.

### 6.2. Фильтры в списках ДИ

Везде, где показывается список ДИ, — единая панель фильтров:
- По типу (чекбоксы: 4 типа).
- По компании (cascade).
- По подразделению (cascade, зависит от компании).
- По дате (диапазон).
- По тексту (поиск по содержимому).

## 10. Критерии приёмки

1. Во всех вкладках ДИ отображаются через единую карточку `<DICard />` с
   обязательными полями (§3.1).
2. 4 типа ДИ имеют единую цветовую индикацию во всём сервисе.
3. При генерации новой ДИ можно выбрать архивную ДИ как базу; текст архивной ДИ
   попадает в промпт как референс; связь `sourceArchiveId` сохраняется.
4. Единый каскадный селектор «компания → подразделение → должность» применяется
   во всех вкладках с поиском/выбором; в массовой генерации — множественный режим.
5. `tsc --noEmit` → 0 ошибок; `eslint .` → 0 ошибок.
6. Миграция применена без потери данных.
7. Git commit с описанием фазы.

## 11. Этапы реализации

1. **Схема**: `sourceArchiveId` + relation + индекс → `db:push`.
2. **API**: `ai-generate` принимает `archiveDIId`; `generated-di`/`archive-di`/`search` возвращают `type` и связи.
3. **Компонент `<DICard />`**: единая карточка с 4 типами и действиями.
4. **`CascadePositionSelector`**: режим `multi`.
5. **`<DISelector />`**: выбор ДИ после каскада.
6. **Интеграция**: внедрить карточку и селекторы во все вкладки (§9).
7. **Проверки**: tsc, lint, ручной прогон по вкладкам.
8. **Фиксация**: AGENT_LOG.md §23 + git commit.
