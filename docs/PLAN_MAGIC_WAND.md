# План: Magic Wand Editor для ДИ

## 1. Как есть (AS-IS)

### 1.1 Текущий редактор ДИ

В сервисе существуют **две формы редактирования ДИ**:

#### A. Ручное создание (Manual Creation)
- **Где:** `src/components/modules/generation.tsx`, viewMode === `'manual'`
- **UI:** Секции в виде expandable Cards (аккордеон). Каждая секция:
  - Заголовок (редактируемый Input)
  - Раскрываемое тело: Textarea для контента (min-h-[200px])
  - Кнопка «Сгенерировать ИИ» — вызывает `/api/generate-di/ai-section` (manualMode)
  - Кнопка «Очистить»
  - Drag-реордеринг (стрелки вверх/вниз)
  - Бейдж: «ИИ» / «Вручную» / «Пусто»
- **Контекст:** Выбран шаблон-пресет, каскадный селектор должности

#### B. Редактор существующей ДИ (Editor View)
- **Где:** `src/components/modules/generation.tsx`, viewMode === `'editor'`
- **UI:** Плоский список секций, каждая:
  - Название секции (Label)
  - Textarea (min-h-[120px])
  - Две кнопки: «Сгенерировать ИИ» (регенерация) и «Улучшить» (диалог)
  - Микро-статистика под текстом: слова, сложные предложения, % воды
  - Глобальная статистика сверху: общее кол-во слов/символов, water%
- **Диалог «Улучшить»:** Textarea с инструкцией → `POST /api/generate-di/ai-improve` → замена текста

#### C. Позиционный воркспейс (Position DI Workspace)
- **Где:** `src/components/modules/position-di-workspace.tsx`
- **UI:** Табы: Архив / Генерация / Сравнение / Утверждение
- Просмотр секций в read-only ScrollArea, без inline-редактирования

### 1.2 Текущие API для редактирования

| Endpoint | Что делает | Ограничения |
|---|---|---|
| `POST /api/generate-di/ai-section` | Перегенерирует секцию по customPrompt или manualMode | Только замена целиком; нет partial-правок |
| `POST /api/generate-di/ai-improve` | Улучшает секцию по инструкции пользователя | Нужен диалог; нет пресетов; нет diff |
| `PUT /api/generated-di` | Сохраняет все секции + авто-версионирование | Без истории правок секции |

### 1.3 Текущие проблемы UX

1. **Нет inline-AI.** Пользователь пишет текст в textarea, потом жмёт «Улучшить» и ждёт модалку. Это разрыв контекста.
2. **Нет diff.** После AI-правки невидно, что именно изменилось. Пользователь должен сам сравнивать в голове.
3. **Нет пресетов улучшения.** Каждый раз вводить «Сделай формальнее» — рутина. Нет кнопок «1-клик».
4. **Нет подсветки проблем.** Water-фразы видны только в микро-бейджах под секцией, а не подсвечены в тексте.
5. **Нет истории.** Если AI испортил текст — нет «Отменить» кроме Ctrl+Z в браузере. При обновлении страницы история теряется.
6. **Одинарная textarea.** Неудобно для длинных текстов — нет rich formatting, нет нумерации пунктов.

## 2. Как будет (TO-BE): Magic Wand Editor

### 2.1 Видение

Редактор ДИ превращается из «текстовой области с кнопкой Сгенерировать» в **AI-ассистированный документ-редактор** уровня Notion / Google Docs с «волшебной палочкой» для каждой секции.

Ключевой принцип: **AI-действия inline, рядом с текстом, без модальных окон и без потери контекста.**

## 3. Фичи по порядку (этапы реализации)

### Этап 1. Magic Wand Toolbar (1-click AI actions)

**Проблема:** Каждый раз вводить инструкцию в диалог «Улучшить» — рутина.

**Решение:** Inline-панель с 6 пресетными кнопками, появляющаяся при focus в Textarea.

**Пресеты:**
| Кнопка | Промпт для AI | Когда нужно |
|---|---|---|
| 🪄 **Усилить детализацию** | «Добавь конкретики: примеры, критерии выполнения, ответственные системы» | Текст расплывчатый |
| 🪄 **Сократить на 30%** | «Сократи текст на 30%, сохранив смысл. Удали повторы и избыточные формулировки» | Текст слишком длинный |
| 🪄 **Формализовать** | «Перепиши в строго формально-деловом стиле. Убери разговорные обороты» | Текст неформальный |
| 🪄 **Упростить язык** | «Объясни простым языком. Каждый пункт — одним предложением. Убери канцеляризмы» | Для линейных должностей |
| 🪄 **Добавить KPI** | «Добавь к каждой обязанности измеримый показатель эффективности» | Для руководителей |
| 🪄 **Переписать стиль** | «Перепиши текст в стиле типовой ДИ компании [название]» | Для единообразия |

**UI:**
- Панель появляется под Textarea при фокусе
- Кнопки в ряд, размер sm, с иконками Lucide
- Disabled во время loading
- Каждая кнопка имеет tooltip с описанием промпта

**API:**
- Расширить `POST /api/generate-di/ai-improve`:
  ```ts
  { sectionId: string, instruction: string, preset?: 'detail' | 'shorten' | 'formalize' | 'simplify' | 'kpi' | 'style' }
  ```
- Если `preset` задан — сервер подставляет системный промпт пресета

### Этап 2. Inline Diff (Before / After)

**Проблема:** AI переписал текст — но что именно изменилось? Пользователь вынужден сравнивать в голове.

**Решение:** После получения ответа от AI показывается не финальный текст, а **diff-предпросмотр**.

**UI:**
- Поверх Textarea появляется split-view или overlay с diff
- `wordDiff()` (уже есть в `src/lib/diff.ts`) раскрашивает:
  - `remove` — розовый фон + зачёркивание
  - `add` — зелёный фон
  - `same` — без изменений
- Режимы просмотра: «Все изменения» | «Только добавления» | «Только удаления»
- Кнопки: **[✓ Применить]** **[↩ Откатить]**
- Если пользователь жмёт «Применить» — текст заменяется, создаётся запись в истории

**UX-фича:**
- Diff показывается **inline** прямо в тексте, а не в отдельном блоке — это снижает когнитивную нагрузку
- Подсветка миганием на 1.5 сек (framer-motion) при появлении

### Этап 3. История правок секции (Undo/Redo)

**Проблема:** AI испортил текст, пользователь обновил страницу — всё пропало. Нет Ctrl+Z для AI-действий.

**Решение:** Каждая секция хранит стек правок в React-state (useReducer).

**Структура истории:**
```ts
interface SectionHistoryEntry {
  id: string           // uuid
  timestamp: Date
  action: 'manual' | 'ai-generate' | 'ai-improve'
  preset?: string      // какой пресет Magic Wand
  prompt?: string      // если было через чат
  beforeSnapshot: string
  afterSnapshot: string
  applied: boolean     // false = в diff-предпросмотре, не применено
}
```

**UI:**
- Таймлайн правок внизу секции (сворачиваемый)
- Каждая запись: иконка (рука/робот), время, действие, кнопка «↩ Вернуть»
- Ctrl+Z / Ctrl+Shift+Y — global hotkeys для undo/redo
- Лимит: 20 записей в стеке (LRU), чтобы не перегружать память

**Сохранение:**
- При `handleSaveDI()` — вся история сериализуется и сохраняется в БД (новая таблица `SectionEditHistory`)
- При открытии редактора — история подгружается

**Новая модель БД:**
```prisma
model SectionEditHistory {
  id          String   @id @default(cuid())
  sectionId   String
  section     GeneratedDISection @relation(fields: [sectionId], references: [id], onDelete: Cascade)
  action      String   // 'manual' | 'ai-generate' | 'ai-improve' | 'ai-magic-wand'
  preset      String?  // 'detail' | 'shorten' | ...
  prompt      String?
  beforeText  String   @db.Text
  afterText   String   @db.Text
  createdBy   String?  // userId или 'ai'
  createdAt   DateTime @default(now())
}
```

### Этап 4. AI-чат по секции (Contextual Chat)

**Проблема:** Пользователь хочет что-то нестандартное, не попадающее в пресеты. Сейчас — только диалог «Улучшить» с одним полем.

**Решение:** Встроенный в секцию чат с AI, который знает контекст всей ДИ.

**UI:**
- Кнопка 💬 рядом с Magic Wand — открывает панель чата (слайд сбоку или drawer снизу)
- Чат в формате диалога: User → AI → User → AI
- AI отвечает не текстом, а **предлагает правку** в формате diff
- Пользователь может «Применить» прямо из чата

**Контекст чата:**
- Системный промпт содержит:
  - Название должности, подразделения, компании
  - Название текущей секции
  - Текст текущей секции
  - Тексты соседних секций (для контекста)
  - Правовой контекст (если есть)

**API:**
- Новый endpoint: `POST /api/generate-di/ai-chat`
  ```ts
  {
    sectionId: string,
    messages: ChatMessage[],  // история диалога
    currentSectionText: string,
    context: { position, department, company, otherSections }
  }
  ```
- Ответ: `{ type: 'suggestion', diff: DiffSegment[], explanation: string }`
- Или: `{ type: 'question', text: string }` — AI уточняет детали

### Этап 5. Подсветка проблем в тексте (Water / Complexity / Legal)

**Проблема:** Water-фразы и сложные предложения видны только в бейджах под секцией, а не в самом тексте. Пользователь не знает, где именно проблема.

**Решение:** Подсветка inline в Textarea (или overlay поверх).

**Технология:**
- Textarea не поддерживает rich highlighting → используем **contenteditable div** или **overlay-approach**
- Overlay: прозрачный div с абсолютным позиционированием поверх textarea, дублирующий текст с `<mark>`
- Библиотека: `@codemirror/view` (легковесный) или кастомный React-компонент

**Что подсвечиваем:**
| Тип | Цвет | Что это |
|---|---|---|
| Water-фраза | Жёлтый фон `bg-amber-100` | «в установленном порядке», «иные обязанности» и т.д. |
| Сложное предложение (>25 слов) | Красное подчёркивание `border-b border-red-300` | Предложение требует разбивки |
| Пассивный залог | Синий фон `bg-blue-50` | «документы составляются» → «составляет документы» |
| Отсутствие субъекта | Фиолетовый фон | «Проводится анализ» — кто проводит? |
| Сомнительная формулировка | Оранжевый фон | «В случае необходимости», «по мере нужды» |

**Взаимодействие:**
- Hover на подсветку → tooltip с объяснением и кнопкой «🪄 Исправить AI»
- Клик → всплывает меню: «Исправить» | «Игнорировать в этой ДИ» | «Узнать больше»

**API:**
- Локальный анализ (без AI): `analyzeText()` уже есть в `src/lib/text-analysis.ts`
- Дополнить функцию: детекция пассивного залога, отсутствия субъекта

### Этап 6. Smart Suggestions ( proactive AI )

**Проблема:** Пользователь пишет текст сам и не знает, что можно улучшить. AI ждёт, пока его спросят.

**Решение:** AI предлагает улучшения **проактивно**, когда пользователь закончил печатать (debounce 3 сек).

**UI:**
- В правом верхнем углу Textarea появляется мягкий бейдж: «AI нашёл 3 возможности улучшить»
- Клик — раскрывается список:
  - «Предложение 2 слишком длинное — разбить?» [Исправить]
  - «Фраза «в установленном порядке» — заменить?» [Исправить]
  - «Можно добавить KPI к обязанности №3» [Добавить]
- Пользователь кликает — применяется конкретное изменение

**API:**
- `POST /api/generate-di/ai-suggest` — лёгкий запрос (быстрая модель, maxTokens 512)
- Ответ: массив suggestion-объектов с позицией в тексте

### 4.3 Компоненты для замены

| Текущий | Новый | Где |
|---|---|---|
| `generation.tsx` (editor view lines 1173-1206) | `DiSectionEditor` | Редактор существующей ДИ |

| «Улучшить» Dialog | `AiChatPanel` + inline diff | Убрать, заменить на Magic Wand |

### 4.4 State management

```ts
// useSectionHistory.ts
interface SectionState {
  currentText: string
  history: SectionHistoryEntry[]
  historyIndex: number  // для undo/redo
  pendingDiff: { before: string; after: string; segments: DiffSegment[] } | null
}

const reducer = (state, action) => {
  switch (action.type) {
    case 'AI_SUGGESTION_RECEIVED':
      return { ...state, pendingDiff: action.payload }
    case 'APPLY_DIFF':
      return {
        ...state,
        currentText: state.pendingDiff.after,
        history: [...state.history, newEntry(state.pendingDiff)],
        historyIndex: state.history.length,
        pendingDiff: null,
      }
    case 'REJECT_DIFF':
      return { ...state, pendingDiff: null }
    case 'UNDO':
      return undo(state)
    case 'REDO':
      return redo(state)
  }
}
```

## 6. Метрики успеха

| Метрика | Было | Станет |

| Время правки одной секции | 5–10 мин (ручное + диалоги) | 1–2 мин (1 клик Magic Wand) |
| % откатов AI-правок | Неизвестно (нет истории) | <15% (благодаря diff-предпросмотру) |
| Использование AI при редактировании | 30% | 80% |
| Удовлетворённость пользователей (опрос) | — | >4.0/5 |
| Кол-во water-фраз в финальных ДИ | ~12% | <5% (подсветка + 1-клик исправление) |

## 7. Риски и mitigations

| Риск | Mitigation |
|---|---|
| Overlay подсветки ломает производительность на больших текстах | Виртуализация текста >3000 символов; debounce анализа |
