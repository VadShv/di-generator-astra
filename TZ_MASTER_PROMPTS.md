# ТЗ: Доработка вкладки «Мастер-промпты»

> Статус: готово, ожидает начала реализации.
> Связанный лог: `AGENT_LOG.md` (раздел 21).

## 1. Контекст и текущее состояние

Вкладка «Мастер-промпты» — центральная библиотека шаблонов запросов к ИИ,
которая определяет качество генерации, аудита и улучшения должностных
инструкций. Сейчас реализованы:

- 4 категории (generation / audit / improvement / ai_culture);
- версионирование (группировка по имени, активная версия);
- переменные `{{должность}}`, `{{подразделение}}`, `{{юр_лицо}}`,
  `{{квалификация}}`, `{{код_должности}}`, `{{бизнес_функция}}` и произвольные;
- условия применимости (department / businessFunction / grade / functionType);
- резолвер (подбор промпта по должности со score);
- фильтры (название, подразделение, активность, категория).

## 2. Выявленные слабые места

1. Редактор промпта — примитивный `Textarea` без подсветки переменных и
   автодополнения.
2. Нет предпросмотра рендера промпта с подставленными данными должности.
3. Нет тестирования промпта — нельзя запустить генерацию прямо из редактора.
4. Нет цепочек промптов (generation → improvement → audit) как сущности — только
   разрозненные вызовы `resolveMasterPrompt` по категориям.
5. Версионирование: нельзя откатиться к старой версии в один клик, нет diff.
6. Резолвер в UI не показывает альтернативы (только лучший матч), хотя API
   возвращает `evaluatedPrompts`.
7. `functionType` не учитывается в `resolveMasterPrompt` (lib), хотя есть в
   API `/resolve` — несогласованность логики.
8. Нет валидации конфликтов: можно создать несколько активных промптов с
   одинаковыми критериями → неоднозначный резолв.
9. Условия применимости ограничены (нет привязки к юр. лицу, конкретной
   должности).
10. Нет импорта/экспорта промптов, тегов, поиска по содержимому.
11. Нет метрик эффективности промптов (успешность, время, оценки).
12. Нет шаблонов-пресетов для быстрого старта.

## 3. Цели доработки

Сделать вкладку гибким и эффективным инструментом:

- ускорить создание и итерацию промптов (умный редактор, пресеты, тест);
- сделать резолв прозрачным и предсказуемым (предпросмотр, альтернативы,
  валидация конфликтов);
- добавить управление цепочками промптов как полноценной сущностью;
- расширить аналитику (метрики, история применения);
- улучшить навигацию (теги, поиск по содержимому, импорт/экспорт).

## 4. Схема данных (изменения Prisma)

**MasterPrompt** — расширить:

- `companyId String?` — привязка к юр. лицу (null = все);
- `positionId String?` — привязка к конкретной должности (null = все);
- `tags String @default("[]")` — JSON-массив тегов;
- `estimatedTokens Int?` — оценка длины промпта в токенах;
- `lastUsedAt DateTime?` — последнее применение при генерации;
- `useCount Int @default(0)` — счётчик применений.

**Новая модель PromptChain** — цепочка промптов:

- `id`, `name`, `description`;
- `steps Json` — массив шагов: `[{category, order, stopOnError}]`;
- `isActive Boolean`;
- `createdAt`, `updatedAt`.

**Новая модель PromptTestResult** — результат теста промпта:

- `id`, `masterPromptId`, `positionId`;
- `providerId` — какой ИИ-провайдер;
- `response String` — ответ модели;
- `durationMs Int` — время генерации;
- `rating Int?` — оценка пользователя (1–5);
- `createdAt`.

**MasterPromptVersion** — расширить:

- `diff String?` — краткое описание отличий от предыдущей версии;
- `createdBy` уже есть.

## 5. Функциональные требования

### Ф1. Умный редактор промпта

- Подсветка переменных `{{...}}` в тексте (визуальное выделение цветом).
- Панель доступных переменных: клик вставляет `{{переменная}}` в курсор.
- Счётчик символов и оценка токенов (эвристика ~4 символа = 1 токен).
- Автосохранение черновика (localStorage) — защита от потери данных.

### Ф2. Предпросмотр рендера

- Кнопка «Предпросмотр»: выбор должности → рендер промпта с подставленными
  переменными через `renderPrompt` + `buildContextFromPosition`.
- Подсветка нерешённых переменных (остались `{{...}}`).

### Ф3. Тестирование промпта (тест-генерация)

- Кнопка «Тест»: выбор должности + активного ИИ-провайдера → реальный запрос
  к модели через `ai-connector`, результат сохраняется в `PromptTestResult`.
- Показ ответа модели, времени генерации, возможность оценить (1–5 звёзд).
- История тестов промпта.

### Ф4. Цепочки промптов

- CRUD цепочек: имя, описание, последовательность шагов (категории промптов).
- Конструктор шагов: drag-and-drop порядок, выбор категории на каждом шаге,
  флаг «стоп при ошибке».
- Активация цепочки (одна активная на категорию применения).
- Запуск цепочки: генерация → улучшение → аудит с прогрессом.

### Ф5. Улучшенный резолвер

- В UI «Тест резолвера»: таблица ВСЕХ подходящих промптов с их score и
  деталями совпадения (использовать `evaluatedPrompts` из ответа API).
- Подсветка лучшего матча и причин выбора.
- Согласованность: `functionType` учитывать и в lib `resolveMasterPrompt`.

### Ф6. Валидация конфликтов

- При активации промпта проверять: нет ли другого активного промпта с теми
  же category + условиями применимости. Предупреждать пользователя.
- Индикатор конфликтов в списке промптов.

### Ф7. Версионирование — откаты и diff

- Кнопка «Откатиться к версии» в истории версий → создаёт новую версию с
  содержимым выбранной (не удаляет историю).
- Diff между версиями (построчное сравнение содержимого).
- Поле «Описание изменений» при сохранении новой версии.

### Ф8. Навигация и организация

- Теги: добавление/удаление тегов на промпт, фильтр по тегу.
- Поиск по содержимому промпта (а не только по названию).
- Импорт/экспорт промптов в JSON (массовый экспорт выбранных, импорт из файла).
- Шаблоны-пресеты: готовые промпты для быстрого старта (кнопка «Из шаблона»).

### Ф9. Метрики эффективности

- Счётчик применений (`useCount`) и последнее использование (`lastUsedAt`).
- В списке промптов: бейдж «применён N раз», дата последнего использования.
- Интеграция: при генерации ДИ инкрементировать `useCount` промпта.

## 6. API-изменения

**Расширить `/api/master-prompts`:**

- GET: поддержка `?tag=`, `?search=` (по content), `?companyId=`.
- POST/PUT: приём `tags`, `companyId`, `positionId`, `estimatedTokens`.
- PUT: приём `description` как «описание изменений версии».
- Новый endpoint активации с валидацией конфликтов: возвращает предупреждение
  при конфликте активных промптов.

**Новый роут `/api/master-prompts/test`:**

- POST: `{promptId, positionId, providerId?}` → рендер промпта, запрос к
  ИИ, сохранение `PromptTestResult`, возврат ответа + длительность.

**Новый роут `/api/master-prompts/preview`:**

- POST: `{content, positionId}` → рендер промпта, возврат текста с
  подставленными переменными и списком нерешённых.

**Новый роут `/api/prompt-chains` (CRUD):**

- GET/POST/PUT/DELETE цепочек.
- POST `/api/prompt-chains/run`: `{chainId, positionId}` → последовательный
  запуск шагов с прогрессом.

**Расширить `/api/master-prompts/resolve`:**

- Уже возвращает `evaluatedPrompts` — UI должен это отображать.
